# 随手复制：两级内容设计说明

## 1. 目标

当保存内容增多时，单层列表会变长，也容易出现多个同名条目。本版把信息架构升级为“一级分类 → 二级文字内容”：主页保持简洁，用户先选择语境，再复制具体正文。

核心任务是：

> 在一级分类中找到需要的二级文字，并用一次点击复制完整正文。

## 2. 需求拆解

| 要求 | 产品决策 | 验收方式 |
| --- | --- | --- |
| 主要显示一级内容 | 首页只渲染分类卡片，不渲染可复制正文 | 首页 DOM 中没有二级复制卡片 |
| 点击进入二级内容 | 整张分类卡片为进入按钮，详情区提供明确返回按钮 | 点击后标题、搜索范围和新增动作切换到当前分类 |
| 保留一键复制 | 仅二级卡片主体触发复制 | 编辑、删除、返回等操作不会写入剪贴板 |
| 兼容已有数据 | 旧版平铺内容迁移到系统建立的“未分类” | 升级后条目数量及正文格式不变 |
| 避免误删 | 删除分类时显示关联的二级条数并二次确认 | 确认后分类及其子内容一起删除 |

## 3. 信息架构

### 一级：分类

```js
{
  id: "分类唯一标识",
  name: "分类名称",
  description: "可选说明",
  createdAt: 0,
  updatedAt: 0
}
```

分类卡片展示名称、说明、二级内容数量、最多三个二级标题预览和更新时间。单击卡片进入该分类，不执行复制。

### 二级：文字内容

```js
{
  id: "内容唯一标识",
  groupId: "所属分类标识",
  title: "内容名称",
  content: "要复制的完整文字",
  createdAt: 0,
  updatedAt: 0
}
```

每条二级内容只属于一个一级分类。列表显示三行正文预览，但复制时使用未经截断的完整正文。

## 4. 导航与操作

### 建立分类

1. 用户在首页点击“分类”。
2. 填写必填名称和可选说明。
3. 保存后自动进入新分类，让用户可以连续添加二级内容。

### 添加与复制二级内容

1. 在分类详情点击“内容”。
2. 填写内容名称和复制正文，两者均必填。
3. 保存后显示文字卡片；单击卡片主体复制完整正文。
4. 返回按钮回到全部分类，分类卡片同步显示数量和标题预览。

### 搜索

- 一级首页：搜索分类名称、说明以及全部子内容的名称和正文；命中子内容时显示其父分类。
- 二级详情：只搜索当前分类中的内容名称和正文。
- 多个空格分隔的关键词采用“全部匹配”规则。

### 删除

- 二级内容：卡片内二次确认后删除，并更新父分类时间。
- 一级分类：若包含子内容，确认区明确显示将同时删除的条数；确认后级联删除。

## 5. 数据迁移

数据版本从 `1` 升级为 `2`。读取旧结构时：

1. 建立名称为“未分类”的一级分类。
2. 为每条旧内容补上该分类的 `groupId`。
3. 保留正文原始换行和首尾空格、原 ID 及时间字段。
4. 自动写回新结构，后续不再重复迁移。

若新版数据中出现所属分类缺失的孤立内容，也会归入“未分类”，优先保留用户数据。

## 6. 视觉与无障碍

- 一级卡片使用稳定的多色标识，但交互主色仍保持紫色。
- 详情顶部显示返回按钮、当前分类名称、说明和编辑入口，形成清楚的层级线索。
- 展开面板宽 372px；窄屏保留 12px 安全边距。
- 使用语义化按钮、动态 `aria-label`、键盘焦点和状态播报。
- 支持系统深色模式、减少动画偏好和 Shadow DOM 样式隔离。

## 7. 数据与安全

- 只申请 `storage` 权限，不申请常驻剪贴板权限。
- 复制必须由用户单击触发；Clipboard API 失败时才使用兼容回退。
- 用户文字通过 `textContent` 写入 DOM，不作为 HTML 解析。
- 不发送网络请求、不加载第三方脚本、不记录浏览历史。
- 数据存放在 `chrome.storage.local`，不适合密码、私钥等机密信息。
