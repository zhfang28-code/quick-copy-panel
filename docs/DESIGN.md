# 随手复制：需求分析与设计说明

## 1. 目标

用户在浏览网页时经常重复输入地址、客服回复、提示词、常用命令等文字。本扩展把这些内容放在始终可达的网页右侧，通过一次单击完成复制，同时尽量少遮挡网页。

核心任务可以概括为：

> 保存一段带名称的文字，并在任何普通网页上用一次点击复制它。

## 2. 需求拆解

| 原始要求 | 产品决策 | 验收方式 |
| --- | --- | --- |
| 浏览器右侧悬浮 | 使用固定定位的内容脚本面板，不挤压网页布局 | 普通网页加载后，面板出现在视口右侧 |
| 可缩小与展开 | 展开态为完整面板，收起态为窄标签；状态持久化 | 刷新或打开其他标签页后仍保持上次状态 |
| 添加文字内容 | 内置新增表单，正文最多 10,000 字符 | 保存后立即出现在列表中 |
| 添加主题 / 名称 | 每条正文必须有“名称 / 主题”，最多 80 字符 | 卡片以名称作为主标题 |
| 单击每个内容自动复制 | 卡片主体是独立复制按钮；编辑、删除位于卡片操作区 | 单击主体复制完整正文，操作按钮不触发复制 |

## 3. 信息架构

单条文字卡片的数据结构：

```js
{
  id: "唯一标识",
  title: "名称 / 主题",
  content: "要复制的完整文字",
  createdAt: 0,
  updatedAt: 0
}
```

扩展状态包含数据版本、收起状态和文字卡片数组。临时 UI 状态（搜索词、正在编辑的条目、删除确认）不持久化。

## 4. 主要流程

### 新增

1. 用户点击“新增”。
2. 面板内展开编辑器，不打开新页面或弹窗。
3. 名称和正文均必填；保留正文的换行与首尾空格。
4. 保存后关闭编辑器，新卡片排在最前，并显示成功反馈。

### 复制

1. 用户单击卡片主体。
2. 优先调用 Clipboard API；权限不可用时使用浏览器复制命令回退。
3. 卡片短暂变色，同时出现“已复制：名称”的反馈。

### 删除

1. 用户点击卡片的“删除”。
2. 在卡片内显示二次确认，避免误删。
3. 确认后更新本地存储和列表。

### 收起 / 展开

1. 完整面板通过右上角箭头收起为右侧窄标签。
2. 点击窄标签、浏览器工具栏按钮或快捷键可恢复。
3. 收起状态写入本地存储，并在标签页之间同步。

## 5. 视觉与交互

- 主色使用紫色，复制成功用绿色，删除风险用红色。
- 展开面板宽 372px，高度随视口限制；手机窄屏保留 12px 安全边距。
- 卡片正文显示三行预览，但复制的是未经截断的完整正文。
- 面板采用 Shadow DOM，降低宿主网页 CSS 污染扩展界面的概率。
- 支持键盘焦点、语义化按钮、读屏标签、减少动画偏好和系统深色模式。

## 6. 数据与安全

- 只申请 `storage` 权限，不申请剪贴板常驻权限。
- 复制行为由用户单击触发；Clipboard API 失败时才使用兼容回退。
- 用户文字一律通过 `textContent` 写入 DOM，不作为 HTML 解析。
- 不发送网络请求，不加载第三方脚本，不记录浏览历史。
- 数据存放在 `chrome.storage.local`，适合普通常用文字，不适合密码或私钥。

## 7. 当前边界

首版不包含账号云同步、文件夹、多设备共享、批量导入导出、富文本和浏览器商店发布流程。这些能力不会影响当前核心闭环，可在后续版本按实际使用反馈增加。

## 8. 验收清单

- [ ] Chrome 和 Edge 可以通过“加载已解压”安装，Manifest 无错误。
- [ ] HTTP/HTTPS 普通网页出现右侧面板，网页自身布局不被挤压。
- [ ] 面板可收起和展开，刷新后状态不丢失。
- [ ] 可以新增、编辑和删除文字卡片。
- [ ] 单击卡片复制完整正文，换行和空格保持不变。
- [ ] 编辑和删除按钮不会触发复制。
- [ ] 可通过名称、正文或多个关键词搜索。
- [ ] 新开标签页能读取已保存的数据。
- [ ] 无匹配结果、空列表、保存失败和复制失败都有明确反馈。
- [ ] 窄屏、深色模式和键盘操作可正常使用。
